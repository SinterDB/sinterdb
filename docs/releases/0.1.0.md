## Developer Preview

SinterDB 0.1.0 is the first release you can build a real local project on. You
can install the server and the driver from npm, store and query documents,
restart the server, and find your data again, using only the documentation.

```bash
npm install --global @sinterdb/cli
npm install sinterdb
```

Start with the [quick start](../quick-start.md).

### Highlights

- **Install from npm.** `sinterdb` is the Node.js driver, `@sinterdb/cli` is the
  server (the `sinterd` command), and `sinterdb-protocol` is the wire codec the
  driver uses. They are published from GitHub Actions with provenance, so each
  version links back to the commit and workflow that built it.
- **A promise you can rely on.** From this release, patch versions do not change
  the API, the protocol, or the on-disk format, and breaking changes need a
  minor version and migration notes. See
  [Compatibility and versioning](../compatibility.md).
- **A fixed public API.** The driver's exports are an explicit list, recorded in
  `etc/sinterdb.api.md`, and CI fails when it changes by accident. The
  [API reference](../../README.md#documentation) is generated from the same
  declarations.
- **A documented connection string.** `sinterdb://host:port/database` is stable
  for the `0.x` line. See [Connection strings](../connection-strings.md).
- **Documentation that is tested.** The quick start is run against the real
  server and the real packages, and the configuration reference is compared
  with the server's flags and environment variables, so neither can drift.
- **Docker.** A `Dockerfile`, a Compose example, and a guide. The image runs as
  a non-root user, keeps data in a `/data` volume, and recovers after the
  container is killed. See [Running in Docker](../docker.md).
- **Known limits, written down.** [Known limitations](../limitations.md) lists
  what SinterDB does not do yet (no authentication or TLS, the dataset must fit
  in memory) and the hard limits, and tests compare the table with the code.
- **Benchmarks.** `pnpm bench` measures inserts, indexed and unindexed reads,
  durability modes, and recovery time. See [Benchmarks](../benchmarks.md).
- **An example application.** `examples/todo-app` is a small command-line
  to-do list built on the driver.

### Fixes

- The server no longer stops when a client connection is reset. The error is
  logged as `server.connection_error` and only that connection is closed.
- The server no longer stops when a `find` result is larger than the 16 MiB
  payload limit. A batch now stops at about 8 MiB, and a result that is still
  too large is answered with a `ResultTooLarge` error.
- A document the database cannot store (`undefined`, a function, a `Map`, too
  deeply nested, or too large) now rejects with `SinterDocumentError`
  (`INVALID_DOCUMENT`) instead of a misleading connection error.
- A server started in place of a killed container now takes over the data
  directory lock the container left behind. See `--reclaim-lock` in the
  [configuration reference](../configuration.md).

### Upgrading from 0.0.9

No data or protocol format changed: storage format 2, snapshot format 2, WAL
format 1, and protocol 1 are the same, so a 0.0.9 data directory opens as it is.
Still copy the directory before you try a new version.

Breaking changes, each with what to do:

- The server package is `@sinterdb/cli`. Earlier GitHub release tarballs named
  it `sinterdb-server`. The `sinterd` command is unchanged.
- A few helpers the driver exported by accident are gone, and some malformed
  connection strings are now rejected.
- Documents that cannot be stored now throw `SinterDocumentError`.

The [migration notes](../compatibility.md#migration-notes) list all of them.

### Not yet

SinterDB is a developer preview for local projects. It has no authentication or
TLS, so keep it on `127.0.0.1` or a network you trust. It keeps the whole
dataset in memory. See [Known limitations](../limitations.md) before you depend
on it.
