## Query Engine and Driver Contract

SinterDB 0.3.0 makes the query language rich enough to build on. You can return
only the fields you need, search inside arrays, count and list distinct values
on the server, index several fields at once, group and total documents with an
aggregation pipeline, and cap how long or how far a query may run. The query
rules, including how values of every kind compare, are written down and checked
by tests, and the driver's public API is the contract that libraries such as
the upcoming ODM build on.

```bash
npm install --global @sinterdb/cli
npm install sinterdb
```

Start with the [quick start](../quick-start.md).

### Highlights

- **Projection.** `projection: { name: 1, age: 1 }` returns only those fields,
  and `{ secret: 0 }` leaves one out. The result type follows the projection
  you write. See [Projection](../query-semantics.md#projection).
- **Array queries.** `{ tags: "x" }` matches a document whose `tags` array holds
  `"x"`. `$elemMatch` and `$size` filter arrays, and dotted paths step through
  arrays of documents (`"items.sku"`) or pick an element (`"items.0"`). See
  [Arrays](../query-semantics.md#arrays).
- **Sorting by several fields.** `sort: [["team", 1], ["age", -1]]` breaks ties
  with each later field. Sorting is stable.
- **Counting and distinct values.** `countDocuments()`,
  `estimatedDocumentCount()` and `distinct()` run on the server and return only
  the result.
- **Compound indexes.** `createIndex({ keys: [["team", 1], ["age", 1]] })`
  indexes up to eight fields. The planner uses one for equality and `$in` terms
  on the leading fields and one range on the next. `explain()` shows which
  fields it used. See [Indexes](../indexes.md).
- **Aggregation.** `collection.aggregate(pipeline)` runs `$match`, `$project`,
  `$sort`, `$skip`, `$limit`, `$count` and `$group`. A leading `$match` uses
  indexes, and `$sort` followed by `$limit` keeps only the top results.
  `$group` supports `$count`, `$sum`, `$avg`, `$min`, `$max`, `$first` and
  `$last`. See [Aggregation](../aggregation.md).
- **Query budgets.** `maxTimeMS` and `maxScanned` on `find`, `findOne`,
  `aggregate`, `countDocuments` and `distinct` stop a query that runs too long
  or examines too many documents, with the errors `OperationTimeLimitExceeded`
  and `ScanLimitExceeded`. See [Query budgets](../query-budgets.md).
- **Collation rules.** One table in
  [Query semantics](../query-semantics.md#collation) says how values of every
  kind compare for equality, ranges, sorting and indexes. There is no locale
  and no case folding, and an index never changes a query's result.
- **A driver contract for libraries.** A test builds a small model layer using
  only what `sinterdb` exports, and the package refuses any other import path.
  The recorded API report is checked in CI. See
  [Building on the driver](../compatibility.md#building-on-the-driver).

### Fixes

- An invalid filter on a collection that does not exist is now an error
  (`DocumentValidationFailed`), like every other command that takes a filter.
- `{ tags: { $ne: "x" } }` and `$nin` no longer return documents whose array
  holds the value.

### Upgrading from 0.2.0

The wire protocol is still version 1, but **storage format 2 became 3**. A 0.3.0
server upgrades a 0.2.0 data directory in place on first open, and the upgrade is
one way: a 0.2.0 server refuses the directory afterwards. Make a checked backup
with `sinterd backup`, or copy the directory with the server stopped, before you
start the new server.

What to know, each with what to do:

- Match the driver and server versions. Projection, compound indexes,
  aggregation, query budgets, counting and `distinct` need a 0.3.0 server. A
  0.3.0 driver refuses to send them to an older one with
  `SinterCompatibilityError`.
- Queries now look inside arrays, which changes which documents some filters
  match. Review filters on array fields, especially `$ne` and `$nin`.
- `IndexDefinition` is now a type. Code that extends it needs a change.

The [migration notes](../compatibility.md#migration-notes) list all of them.

### Not yet

SinterDB is a developer preview for local projects. It has no authentication or
TLS, so keep it on `127.0.0.1` or a network you trust. It keeps the whole
dataset in memory. An index is not used once an indexed field holds an array,
sorting is not served from indexes, and `$group` cannot collect values into an
array. See [Known limitations](../limitations.md) before you depend on it.
