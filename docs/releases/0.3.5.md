## Interactive CLI

SinterDB 0.3.5 gives `sinterd` a full-screen console. Run `sinterd` with no
options in a terminal and you can start, stop, restart and kill a server, watch
its log as it happens, and inspect, back up and repair its data, all from the
keyboard. The driver, the wire protocol and the storage format are unchanged,
and every existing command and flag behaves as it did in 0.3.0.

```bash
npm install --global @sinterdb/cli
npm install sinterdb
```

Then run `sinterd` in a terminal. The console starts with the server stopped. Press `s` to start it and `?` for
every key. See [Interactive console](../configuration.md#interactive-console).

### Highlights

- **A console for the server.** A header shows the state, address and where the
  data is kept. A stats line shows uptime, open connections, commands per second
  and failures. Below it is a log with follow, pause, a level filter (`l`) and a
  text filter (`/`). Every button has a key.
- **Inspect, Backup and Repair in place.** `i` inspects the data directory,
  even while the server runs. `b` backs it up and `r` shows a repair plan, once
  the server is stopped. They run the same code as `sinterd inspect`,
  `sinterd backup` and `sinterd repair`. Applying a repair plan asks first, and
  steps that need `--rebuild-manifest`, `--clear-lock` or `--allow-data-loss` are
  shown but left to the command line.
- **Asks before it is destructive.** `k` kills the server without a clean
  shutdown and `q` stops a running server before it quits. Both ask first, and
  a second ctrl-c while quitting kills the server.
- **A config file.** `sinterd config get`, `set`, `list` and `unset` read and
  write a JSON file. A flag wins over an environment variable, which wins over
  the file, which wins over the default. A change that needs a restart says so.
  See [Configuration](../configuration.md).
- **`--no-ui` and the `ui` setting** keep the plain behavior on a terminal.
- **Structured log events.** The server's log carries operation and connection
  events that the console reads. The log format is unchanged, and operations
  are logged only with `--log-operations`.

### Behavior change

A bare `sinterd` in an interactive terminal now opens the console. Before, it
started a server in that terminal. See the
[migration note](../compatibility.md#035).

### Not changed

- The driver API, the wire protocol (still 1) and the storage format (still 3).
- Any command or flag. Scripts, Docker, systemd and CI keep working, because the
  console needs a terminal on standard input, output and error, and the Docker
  image configures the server through environment variables.
